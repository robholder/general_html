      • (It's checked out - in your sandbox)

Unlocking

To Explore ONLY

If you try to snoop inside a locked module, you will get 'Permission Denied'.

To explore a node/packet (without checking out):

  • RMB on the node graph while inside a task/node
    • Allow Editing of Contents

This allows you to click around and see what's going on, including viewing the Lightbox node, and other nodes.

⛔ DON'T MODIFY ANYTHING! ⛔

⚠️ Caution ⚠️

Unlocking will prevent updates from upstream.

The node which has been unlocked will have a crossed-out circular warning.

To restore inheritance, either:

  • RMB on the node graph and choose:
    • Match Current Definition
    • You'll get a lot of errors on a message box
  • -HOTL shelf:
    • Upgrade to Latest
      YOU'LL LOSE ANY CHANGES IF YOU UPDATE.

"Update Available"

Apparently, there will be an indication of any available updates on the node in question (if a new version is published). I haven't seen an example, but I assume it's visible on the parm panel of the node.

There is a tool on the HOTL toolbar which might elude to 'upgrade to the latest'. Haven't seen, but that's what has been mentioned.

To Actually Edit

Only edit if you are Authorized to work in that HOTL!

  • RMB > HOTL > Check-out

If you Are in a checked-out state, this option with be switched to Commit... in the context menu:

  • RMB > HOTL > Commit...
    ⚠️ ONLY COMMIT WHAT YOU ARE AUTHORIZED TO! ⚠️

RegionGrad Layout

If you are adding multiple RegionGrads make them in parallel (not 'inline') and plug into the merge_RgradShapes node.

More efficient: This way, changing one won't force all to re-cook.

Lightbox panel

Don't 'pin' a parameter pane with Lightbox on it! This causes a re-cook for every change.

Instead use the dedicated Lightbox pane.
