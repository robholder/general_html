Fixing 'rm' Deleted Files (Locally)

If you used rm locally but haven't committed the deletion yet, your deleted files are still safely stored in your last commit (HEAD).

Because you have other modified files and new untracked files that you want to keep, you shouldn't do a blanket reset. Instead, you can target only the deleted files using a Git filter, which leaves your new files and local modifications completely untouched.

Identify currently deleted tracked files: Audit deletions.

Run this command to see a list of files that were tracked and deleted via rm, without touching anything else: 

git diff --name-only --diff-filter=D

Verification: The terminal prints the paths of only the files you accidentally deleted.

Restore only the deleted files: Targeted recovery.

Feed that list directly into git restore to pull them back from HEAD: 

git checkout HEAD -- $(git diff --name-only --diff-filter=D)

(Alternatively, on newer git versions: git restore $(git diff --name-only --diff-filter=D))

Verification: Run git status. You should see your deleted files reappear as restored, your modified files remain safely modified, and your new files remain untouched.
