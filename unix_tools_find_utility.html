find

Linux find Command: Reference & Practical Guide

The find utility is one of the most powerful tools in Linux for searching, filtering, and performing actions on files and directories. Below is a comprehensive reference guide covering its syntax, core flags, advanced execution options, and real-world workflows.

1. Basic Syntax

find [path(s)] [expression]
  • path(s): The directories where the search begins. Defaults to the current directory (.) if omitted.
  • expression: Made up of tests, actions, and operators that filter and process the results.

2. Core Options & Flags

Filtering by Name & Type

  • -pattern: Matches files whose names match a shell pattern (supports wildcards). Example: -name "*.txt".
  • -iname pattern: Case-insensitive version of -name. Example: -iname "*.jpg".
  • -type [f|d|l]: Filters by file type (f for regular files, d for directories, l for symbolic links).
  • Note: You cannot combine multiple types in a single -type flag; use logical operators instead (e.g., \( -type f -o -type d \)).

Filtering by Size & Time

  • -size [+/-]n[c|k|M|G]: Matches files by size (c bytes, k kilobytes, M megabytes, G gigabytes). + means greater than, - means less than. Example: -size +100M.
  • -mtime n / -atime n / -ctime n: Filters by modification, access, or change time in days. +n means older than ＄n＄ days; -n means newer than ＄n＄ days.

Filtering by Permissions & Ownership

  • -perm mode: Filters files by permissions.
  • -perm 644: Exact match.
  • -perm -644: Files must have at least these bits set (may have extra).
  • -perm /644: Files match if any of these bits are set.
  • *-user name / -group name*: Matches files owned by a specific user or group.

Depth & Traversal Limits

  • -maxdepth n: Restricts search depth to ＄n＄ levels (e.g., -maxdepth 1 checks only the target directory without recursing).
  • -mindepth n: Skips top-level matches and starts matching only from depth ＄n＄.
  • -prune: Prevents find from descending into specific directories (e.g., skipping .git folders).

3. Command Execution (-exec)

You can run external commands on every matching file using -exec.

  • {}: Acts as a placeholder replaced by the path of each matching file.
  • \;: Terminates the command, executing it once per file.
  • +: Terminates the command, batching multiple file paths into a single command invocation for better efficiency (supported by tools like rm, cp, grep, and ls).

Examples

# Run individually per file
find . -type f -name "*.log" -exec rm {} \;

# Batch-process files for efficiency
find . -type f -name "*.log" -exec rm {} +

# Interactive prompt before executing
find . -type f -name "*.conf" -ok grep -H "setting" {} \;

4. Logical Operators & Grouping

  • -a (or implicit space): Logical AND. Tests must both be true.
  • -o: Logical OR. Matches if either test is true.
  • -not or !: Logical NOT. Negates a test.
  • Parentheses \( ... \): Used for grouping complex conditions (remember to escape them in your shell).

5. Practical Real-World Case Studies

Case Study A: Cleaning Up and Renaming Legacy Render Frames

Scenario: A render sequence changed from 1 to 85 frames down to 1-84, leaving behind rogue frame 85 files across deeply nested subdirectories.

  1. Preview the files first: 
find . -name "*0085*"
  1. Delete the matching files safely: 
find . -name "*0085*" -exec rm {} \;

Alternative Addendum: Copying and renaming files using shell parameter expansion

If you need to copy and rename files (e.g., duplicating frame 84 as frame 85 to patch a gap), you can pipe find into a mini shell script: 

find . -name "*.0084.exr" -exec sh -c 'cp "$1" "${1%0084.exr}0085.exr"' _ {} \;

How the parameter expansion works (＄{1%pattern}replacement):

  • ＄{1}: The file path argument passed in (e.g., ./shots/shot_01.0084.exr).
  • %0084.exr: Strips the suffix matching 0084.exr from the right.
  • Immediately appending 0085.exr replaces the suffix, yielding ./shots/shot_01.0085.exr.

Case Study B: Filtering and Managing Files Older Than a Specific Date

To target files based on a hard calendar date rather than relative days, use the GNU -newermt flag.

  1. Preview files older than 18th September 2026: 
find . -type f -not -newermt "2026-09-18"
  1. Delete them safely: 
find . -type f -not -newermt "2026-09-18" -delete
  1. *Alternatively, relocate them to an existing remove directory:* 
find . -type f -not -newermt "2026-09-18" -exec mv -n -t remove {} +

*(Using -n prevents accidental overwriting of files with identical names).*

6. Summary of Common -exec Utilities

Utility Common Use Case Example Command
rm Delete files find . -name "*.bak" -exec rm {} \;
mv Move/archive files find . -name "*.tmp" -exec mv {} /archive/ \;
cp Backup files find . -name "*.conf" -exec cp {} /backup/ \;
chmod Fix permissions find . -name "*.sh" -exec chmod 755 {} \;
grep Search file contents find . -name "*.log" -exec grep -H "ERROR" {} +
sed In-place text replacement find . -name "*.txt" -exec sed -i 's/old/new/g' {} \;
