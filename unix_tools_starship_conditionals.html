Starship - Conditionals

Starship supports conditional formatting for prompts through conditional format strings enclosed in parentheses (...), which hide content if all internal variables are empty.

Conditional Features

  • Visibility Control: Any text and variables wrapped in parentheses will only render if at least one variable inside the group evaluates to a non-empty value. For example, (@\(region) displays @ and the region name only if the \)region variable exists; otherwise, it outputs nothing.
  • Module-Level Triggers: Individual modules automatically turn on or off contextually depending on environmental indicators (like detecting local Git repositories, configuration files, or active cloud contexts).
  • Custom Module Conditions: Custom modules can use the when configuration option with a custom command or environment check to determine whether they should run.

QUESTION

Can you have conditionals based on the value of an env var?

ANSWER

Yes, you can, but not directly within Starship's core layout engine, as starship.toml does not support native if/else logic statements. Instead, you can achieve this cleanly using two official methods: Custom Modules with shell commands or Conditional Format Strings based on variable existence.

Method 1: Custom Modules with when Conditions (Recommended)

You can create a custom module that runs a shell evaluation command inside the when parameter. If the shell command returns an exit code of 0 (true), the module triggers; if it fails, the module remains completely hidden.

Add this to your starship.toml: 

# 1. Register your custom module in the main layout
format = """
$directory\
$custom.env_check\
$character
"""

# 2. Define the conditional logic
[custom.env_check]
# Executes a shell command to check the exact value of your environment variable
when = 'test "$MY_ENV_VAR" = "production"' 
command = 'echo "⚠️ PROD"'
style = "bold red"
format = "[$output]($style) "

Method 2: Conditional Format Strings (Existence Only)

If you only need to check whether an environment variable exists and is not empty (regardless of its specific value), you can use Starship's native environment variable module paired with a conditional format string. 

# Main layout using conditional syntax (parentheses)
format = """
$directory\
(${env_var.STAGE} )\
$character
"""

# Define the variable to watch
[env_var.STAGE]
variable = "STAGE"
style = "bold yellow"
  • How it works: The (${env_var.STAGE} ) block will evaluate to absolutely nothing if ＄STAGE is empty or unset. If ＄STAGE is set to "dev", it will cleanly render dev in your prompt.

QUESTION

I need to show a variable in the prompt only IF another variable is NOT a certain value. Is that possible?

ANSWER

Yes, this is completely possible by routing the logic through a Starship custom module. Because Starship's layout strings do not have native unequal/negation syntax (!=), you use the shell's logic inside the module's when condition to control it.

Implementation

Below is a setup that displays the environment variable ＄TARGET_APP only if the variable ＄ENV_TYPE is NOT equal to "production".Add this configuration to your starship.toml file: 

# 1. Place your custom module variable into your layout format
format = """
$directory\
$custom.conditional_display\
$character
"""

# 2. Define the negative logic inside the custom block
[custom.conditional_display]
# The 'when' command must return an exit code of 0 for the module to display.
# In shell scripting, [ ! "$VAR" = "value" ] means "if NOT equal".
when = '[ ! "$ENV_TYPE" = "production" ]'

# If the check passes, fetch and echo the variable you want to show
command = 'echo "$TARGET_APP"'

style = "bold cyan"
format = "via [$output]($style) "

How It Handles Edges

  • If ＄ENV_TYPE is "production": The when condition fails (exits with code 1). The entire module is skipped, completely hiding the text and variable.
  • If ＄ENV_TYPE is anything else (e.g., "staging", "development"): The condition passes. Starship executes the command block, outputs the value of ＄TARGET_APP, and formats it cleanly.
  • If ＄TARGET_APP is empty: Even if the condition passes, echo yields nothing, preventing empty brackets or broken styles from muddying the prompt.

QUESTION

This is working for me. Is it possible to do an 'else' (for a different string for the 'not' situation)?

ANSWER

Yes, you can achieve an "else" behavior, but because a single Starship custom module cannot split into multiple layout branches, you must use two complementary custom modules that act as opposing conditional toggles.

The "If / Else" Dual Module Strategy

To render String A when your condition is met, and String B when it is not, create two separate custom modules with inverted when logic and place them side-by-side in your layout.

Here is how to show ＄TARGET_APP when ＄ENV_TYPE is NOT "production" (the "If" block), and show a generic warning string when it IS "production" (the "Else" block): 

# 1. Place both modules side-by-side. 
# Only one will ever satisfy its 'when' condition at any given moment.
format = """
$directory\
$custom.if_not_prod\
$custom.else_is_prod\
$character
"""

# --- THE "IF" BLOCK ---
# Displays only when $ENV_TYPE is NOT "production"
[custom.if_not_prod]
when = '[ ! "$ENV_TYPE" = "production" ]'
command = 'echo "$TARGET_APP"'
style = "bold cyan"
format = "via [$output]($style) "

# --- THE "ELSE" BLOCK ---
# Displays only when $ENV_TYPE IS "production"
[custom.else_is_prod]
when = '[ "$ENV_TYPE" = "production" ]'
command = 'echo "🔒 PROD-LOCKED"'
style = "bold red"
format = "[$output]($style) "

Why This Works Efficiently

  • Mutual Exclusion: Because the shell evaluation for when in else_is_prod is the exact mathematical inverse of if_not_prod, Starship will never render both simultaneously.
  • No Layout Gaps: Starship completely strips out modules that fail their when command, meaning the inactive module won't leave behind any accidental spaces or broken padding.

QUESION

How can I have the else block be 'nil'? (taking no space and showing nothing?)

ANSWER

To make the Else block completely nil (taking up zero space and showing absolutely nothing), you simply remove the else_is_prod module from your format configuration, or leave its command completely empty.

Starship naturally behaves this way: if a custom module fails its when condition or outputs an empty string, it yields nil space and leaves no trace in your prompt.

Option A: Remove the Else Module Completely (Simplest)

If your "Else" case is truly meant to be blank, you do not need a second module at all. The if_not_prod module you already built will automatically disappear and collapse into nothing when ＄ENV_TYPE is "production". 

# The prompt will automatically collapse to zero space when the condition fails
format = """
$directory\
$custom.if_not_prod\
$character
"""

[custom.if_not_prod]
when = '[ ! "$ENV_TYPE" = "production" ]'
command = 'echo "$TARGET_APP"'
style = "bold cyan"
format = "via [$output]($style) "

Option B: The Blank Return Strategy

If you are building a complex chain where you must explicitly define the module, ensure the command outputs nothing. Starship ignores modules that return an empty string. 

[custom.else_is_prod]
when = '[ "$ENV_TYPE" = "production" ]'
command = '' # Outputting nothing ensures it renders as a true 'nil' layout element
