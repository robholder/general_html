Bash (& Zsh) - Echo Alias Summary

Building a Self-Filtering Command Cheat Sheet in Bash and Zsh

When managing custom shell environments, keeping track of custom aliases, functions, and pipeline tools can become challenging. While adding an echo or cat block to your startup files provides a quick reminder, it often clutter the terminal during sourcing, and managing visibility requires messy maintenance.

This guide details a technique to build a clean, on-demand, self-filtering command summary for Bash and Zsh. It uses a single data block where you can organize items under headers and selectively enable or disable commands using standard comment syntax.

The Complete Implementation

Add the following code block to your shell configuration file (such as ~/.bashrc or ~/.zshrc): 

#------------------------------------------------------------------------------
# PIPELINE COMMAND SUMMARIES & USAGE REMINDERS
#------------------------------------------------------------------------------
function helpnav {
    cat << 'EOF' | grep -v '^[[:space:]]*#'
  
  🚀 Active Pipeline Shortcuts:
  
     ─── Navigation & Setup ──
    cdshot         - Jump to show/seq/shot comp dir & list contents (uses $NAV_SEQ/$NAV_SHOT)
    nshot <sq>     - Set up seq/shot and jump straight to lighting comp
    nh <seq>       - Set sequence number context (or fallback to $MY_SEQ_VAR)

     ─── Environment Resets (Currently Disabled) ──
    # nogig        - Clear PRODUCTION, NAV_SEQ, and NAV_SHOT variables
    # noseq        - Clear NAV_SEQ and NAV_SHOT variables
    # noshot       - Clear only the NAV_SHOT variable

EOF
}
#------------------------------------------------------------------------------

How It Works: Mechanics of the Technique

This technique relies on four distinct shell components working together:

On-Demand Execution via Functions (function helpnav)

Instead of executing the text block every time you open a terminal or run source ~/.bashrc, wrapping the block in a function ensures it remains completely silent until explicitly called. Typing helpnav in your terminal triggers the display.

Literal Text Output via Quoted Heredocs (cat << 'EOF')

The cat << 'EOF' construct (with single quotes around 'EOF') creates a Heredoc.

  • Why single quotes matter: They prevent the shell from attempting to evaluate variables (like ＄NAV_SEQ) or backticks inside the block. The text is printed literally, exactly as written.

Stream Filtering via grep -v

The output of the Heredoc is piped (|) directly into grep -v.

  • The -v flag: This tells grep to invert the match - meaning it excludes lines matching the specified pattern rather than selecting them.

Smart Pattern Matching via Regular Expressions

The regular expression '^[[:space:]]*#' governs what gets hidden:

  • ^ asserts the start of a line.
  • [[:space:]]* accounts for any leading spaces or indentation tabs.
  • # looks specifically for a hash.

Because section headers don't use a hash ( ── Navigation ──), they pass through the filter untouched and remain visible. Because disabled items use a hash (# nogig), the filter catches them and strips them out of the final output.

Use a double hash in the grep string if you need (and comment out with double-hash).
