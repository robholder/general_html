Bash Prompts

Ironing Out Issues in Prompt Scripts

Before building a prompt, it helps to understand what went wrong in the original snippet and how to fix it:

  • Non-Printing Character Escaping (\[ and \]): Bash needs to know which characters take up visual space on the screen and which are purely formatting (like colors). Without wrapping color and style codes in \[ and \], Bash miscalculates line lengths, leading to broken wrapping when text hits the edge of your terminal window.
  • Variable Scope & Evaluation Timing: If you evaluate a dynamic variable or command substitution once when .bashrc loads (using double quotes "), it will never update. Dynamic variables like current time, working directory, or environment states must either use escaped backslashes (so Bash runs them on every prompt redraw) or single quotes '.
  • Undefined Variables: Your original script referenced rh_sgr0, but you defined it as rh_reset=$(tput sgr0). This caused an empty evaluation break.
  • ANSI Formatting Resets: Starting an ANSI escape code (like italics \e[3m) requires a corresponding reset code (\e[23m), or the styling will bleed into subsequent text elements.

The Cleaned & Optimized Reference Script

Here is the fully ironed-out, robust version of your prompt script. Drop this into your ~/.bashrc or ~/.bash_profile. 

###############################################
#  Custom Command Prompt Configuration
###############################################

# 1. Color and Style Variables 
# Using a custom prefix 'rh_' to prevent system/studio clashes.
rh_gray=$(tput setaf 8)
rh_lightgray=$(tput setaf 7)
rh_darkgray=$(tput setaf 245)
rh_lightblue=$(tput setaf 153)
rh_pink=$(tput setaf 183)
rh_teal=$(tput setaf 23)
rh_red=$(tput setaf 160)
rh_orange=$(tput setaf 166)
rh_paleorange=$(tput setaf 172)
rh_yellow=$(tput setaf 228)
rh_green=$(tput setaf 71)
rh_white=$(tput setaf 15)

rh_bold=$(tput bold)
rh_reset=$(tput sgr0)

# 2. Dynamic Environment Checks
# Safely handle production environment variables
prod="${PRODUCTION:-No GIG}"

# 3. Constructing PS1
# - Double quotes allow bash expansion for static variables and tput commands.
# - \[\b\] wrappers protect bash from miscalculating character lengths.
# - Single quotes or escaped variables are used for real-time dynamic evaluation.

PS1=""

# Line 1: Bold spacing and Timestamp
PS1+="\[${rh_bold}\]\n"
PS1+="\[${rh_pink}\]\D{%y%m%d_%H%M:%S}"

# Conditional Production Tag (only displays if $PRODUCTION is active)
# Deferred evaluation via single quotes keeps it dynamic
PS1+='${PRODUCTION:+ \[${rh_green}\][$PRODUCTION]}'

# Line 2: User @ Host in Working Directory
PS1+="\n"
PS1+="\[${rh_lightblue}\]\e[3m\u"             # Username (Italicized)
PS1+="\[${rh_lightgray}\]@"
PS1+="\[${rh_paleorange}\]\h\e[23m"          # Host (End Italics)
PS1+="\[${rh_lightblue}\] in "
PS1+="\[${rh_darkgray}\]\w"                  # Working directory

# Line 3: Prompt Symbol
PS1+="\n"
PS1+="\[${rh_white}\]\$ \[${rh_reset}\]"

export PS1

Anatomy of a Custom Prompt

Color & Styling Engine (tput)

Using tput is superior to hardcoding raw ANSI escape codes because it queries the terminal's termcap database, ensuring compatibility across different terminal emulators.

  • Colors (Foreground)*: tput setaf <number> (0–255 color palette)
  • Modifiers*: tput bold, tput dim, tput sgr0 (resets all attributes).
  • Inline Styles: Standard escape sequences like \e[3m (italics) and \e[23m (stop italics) work well when wrapped correctly.

Essential Bash Escape Sequences

When building your string, Bash recognizes specific backslash-escaped characters natively:

Sequence Meaning Example
\u Current username john_doe
\h Hostname (short version) devbox
\w Current working directory (full path) /home/user/projects
\W Basename of current working directory projects
\$ Privilege indicator (＄for user, # for root) ＄
\n Newline character Creates multi-line layout

Design Best Practices

  • Always Wrap Non-Printing Characters: Enclose every single color assignment, tput command, and style modifier inside \[ ... \]. If you omit this, your command history arrows (Up/Down) will glitch out visually when text wraps.
  • Use Multi-Line Layouts: Cramming everything onto a single line makes navigation difficult when working with long commands or deep directory paths. Using \n to break information (Context -> Location -> Input) keeps things clean.
  • Graceful Fallbacks for Variables: Use parameter expansion like "${PRODUCTION:-No GIG}" to supply safe default states when custom environment variables aren't set.

rh_pink=$(tput setaf 183);

Color Swatches

Quick view of available colors: 

for i in {0..255}; do printf "\x1b[38;5;${i}mcolour%-5s\x1b[0m" "${i}"; if [ $(( ($i + 1) % 8 )) -eq 0 ]; then echo; fi; done

Show available colors in a block style:

for i in {0..255}; do
    printf "\e[48;5;%dm  %3d  \e[0m" "$i" "$i"
    if [ $(( ($i + 1) % 6 )) -eq 0 ]; then
        echo
    fi
done

If you make variables based on these, show them like this: 

echo -e "${rh_pink}■ rh_pink (183) ${rh_teal}■ rh_teal (23) ${rh_orange}■ rh_orange (166)${rh_reset}"

Terminal Background Color

You can configure the terminal background color using a bash config file like .bashrc.

Just like setting foreground colors with tput setaf, you can set background colors using tput setab (set background ANSI/color).

How to Implement It

You can add background color variables alongside your text colors, wrapping them in \[ ... \] when used inside PS1. 

# Set a dark blue background variable
rh_bg_darkblue=$(tput setab 18)
rh_reset=$(tput sgr0)

# Apply it inside your prompt layout
PS1="\[${rh_bg_darkblue}\]\[${rh_white}\] Working on a background color \[${rh_reset}\]\n\$ "

Important Nuances to Keep in Mind:

The "Full Window" Trap: Changing the background color inside PS1 only colors the exact cells/spaces that text occupies, rather than painting the entire background window of your terminal emulator.

The "Bleed" Issue: If your script changes the background color, any text you type or commands you run afterward might inherit that background color unless you explicitly append $(tput sgr0) (or a reset sequence) at the end of your prompt line.
