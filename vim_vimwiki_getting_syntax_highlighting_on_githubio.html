Documentation: Custom Self-Contained Syntax Highlighting for Vimwiki & GitHub Pages

Architectural Overview

This system uses a two-repository workflow:

  1. general (Source Repository): Contains raw Vimwiki .wiki text files and the HTML layout layout file (template.tpl).
  2. general_html (Output Repository): Houses the compiled .html files, global style.css, and a fully self-contained prism/ distribution package. This folder is deployed directly to GitHub Pages (github.io).

By compiling all chosen programming languages directly into a local Prism bundle, the site is immune to GitHub Pages Content Security Policy (CSP) external CDN script blocks and functions perfectly completely offline.

Step 1: Generate the Custom Local Prism Bundle

To avoid keeping a messy components directory or making individual external network requests for different programming languages, a unified asset package is compiled.

  1. Navigate to the official Prism Download Customizer. 
https://prismjs.com/download#themes=prism-tomorrow&languages=markup+css+clike+javascript
  1. Under Compression level, select Minified version.
  2. Under Themes, check the box for Tomorrow Night (or your preference).
  3. Under Languages, select every language you intend to use in your wiki (e.g., Python, Bash, C++, JavaScript, Go, Markdown, etc.). Checking them here bakes the compiler dictionary directly into the main JavaScript script file. (Add all is a good option.)
  4. Under Plugins, check the box for Autoloader.
  5. Scroll to the bottom of the page and download both generated assets:
    • Click Download JS (Saves as prism.js)
    • Click Download CSS (Saves as prism.css)

Step 2: Set Up the Output Repository (general_html)

Your compiled assets must be placed relative to the output build path. Move the downloaded bundle assets into your static asset folder tree inside general_html matching this schema exactly: 

general_html/
├── index.html
├── style.css             <-- Your main page styles
└── prism/                <-- Create this directory
    ├── prism.css         <-- Your custom downloaded theme style sheet
    └── prism.js          <-- Your custom downloaded monolith script file

Step 3: Populate the Source Template (general/template.tpl)

Vimwiki reads template.tpl inside your source text directory to shape your markdown pages into target HTML web layouts.

Because Vimwiki files can live inside subdirectories (nested wikis), utilizing straight absolute strings like href="prism/prism.css" will break structural routing paths on multi-nested subpages. We resolve this by appending Vimwiki’s dynamic macro namespace variable %root_path%. When compiling, Vimwiki calculates and converts this placeholder token back down to the relative root index (e.g., ../../).

Populate general/template.tpl with the following production markup configuration code block: 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>%title%</title>

    <!-- Dynamically maps paths back to your root style.css -->
    <link rel="stylesheet" type="text/css" href="%root_path%style.css">
    
    <!-- Dynamically maps paths back to your local custom root prism.css -->
    <link rel="stylesheet" type="text/css" href="%root_path%prism/prism.css">
</head>
<body>

    <div class="content">
        %content%
    </div>

    <!-- Dynamically maps paths back to your local custom root monolith prism.js -->
    <script src="%root_path%prism/prism.js"></script>

    <script>
        document.addEventListener("DOMContentLoaded", function() {
            if (window.Prism) {
                document.querySelectorAll("pre").forEach(pre => {
                    // 1. Isolate the target language identifier string out of Vimwiki's raw attributes (e.g., <pre python>)
                    let lang = pre.getAttributeNames().find(a => !["class", "style", "id"].includes(a)) || "text";
                    
                    // 2. Clear out any unformatted structural traits and assign the formal Prism standard class selector
                    pre.className = "language-" + lang;
                    
                    // 3. Inject a standard <code> container block loop inside <pre> so Prism's virtual DOM engine parses properly
                    if (!pre.querySelector("code")) {
                        const code = document.createElement("code");
                        code.className = "language-" + lang;
                        
                        // Using textContent explicitly sanitizes raw code strings from leaking as live unsafe HTML elements
                        code.textContent = pre.textContent; 
                        
                        pre.innerHTML = "";
                        pre.appendChild(code);
                    }
                });
                
                // 4. Force a complete scanning pass compilation across the newly normalized layout structures
                Prism.highlightAll();
            }
        });
    </script>
</body>
</html>

Step 4: Execution & Verification Workflow

Whenever you change or edit a wiki document, execute this workflow sequence:

  1. Compile the Wiki: Inside Vim, run your master site generator compilation execution mapping: 
:VimwikiAll2HTML
  1. Local Test: Open a generated HTML file directly out of your local general_html workspace file path inside a web browser to verify structural rendering integrity.
  2. Commit and Deploy Output Repo: Stage and push the freshly generated build artifacts downstream to production: 
cd /path/to/general_html
git add .
git commit -m "Build update: Added code highlighting enhancements"
git push origin main

Within a few moments, GitHub Pages processing will finish building, and your live github.io pages will render seamless, high-performance typography and semantic color syntax processing layout formats securely.
