pwd

Even though pwd (Print Working Directory) looks like one of the simplest commands in Unix/Linux, it hides a few fascinating technical design choices and behaviors under the hood:

1. It Has a "Twin Identity" (Built-in vs. Binary)

When you type pwd, you usually aren't running a standalone program file.

  • TShell Built-in: Most modern shells (like Bash and Zsh) have pwd hardcoded directly into them as a shell built-in for maximum speed.
  • The External Binary: There is also a physical executable file living at /bin/pwd (part of the GNU Coreutils package).

You can see both on your system by running: 

type -a pwd

2. They Have Opposite Default Behaviors

Because there are two versions of pwd, they don't even agree on how to handle symlinks by default:

  • The Shell Built-in (pwd) defaults to Logical mode (-L). It respects the symlink path you just walked through (like your ~/.nuke experience).
  • The External Binary (/bin/pwd) defaults to Physical mode (-P). If you run /bin/pwd inside a symlinked directory, it immediately strips away the shortcut and prints the raw physical path.

3. It Doesn't Always Ask the Kernel

When you use the shell's built-in pwd, it doesn't actually query the hard drive or the Linux kernel's file system table to figure out where you are. Instead, it reads the ＄PWD environment variable, which the shell updates dynamically every time you type cd.

This is why it's lightning-fast: it's just echoing a string the shell is already keeping track of in memory.

4. It Powers the Magic of cd -

Have you ever wondered how typing cd - instantly takes you back to your previous directory?

The shell relies on two companion environment variables that work hand-in-hand with pwd:

  • ＄PWD (Current Working Directory)
  • ＄OLDPWD (Previous Working Directory)

Every time you change directories, the shell swaps these variables. When you type cd -, the shell is essentially just telling itself: cd ＄OLDPWD.

When PWD Tells You Lies

If you navigate to a location via symlinks, pwd might give you a misleading path location (as if the symlink is a real place).

This is completely normal behavior* for modern shells (like Bash and Zsh).

By default, the pwd command operates in logical mode (-L). This means the shell remembers the path you typed to get there—preserving the symlink name (~/.nuke) rather than immediately translating it into the actual physical directory it points to (Documents/dot-nuke).

How to see the physical path instead

If you ever want pwd to resolve the symlink and show you the actual physical target directory on your disk, you can use the -P (physical) flag: 

pwd -P

This will output the resolved path (e.g., /home/username/Documents/dot-nuke). Conversely, pwd or pwd -L will keep showing you the logical symlink path.
