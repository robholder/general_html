SSH on Local Network

Here is a guide for setting up passwordless SSH between:

  • macmini.local and
  • macbook-m3.local

...so interactive logins, file transfers, and BatchMode commands work smoothly.

1. Enable Remote Login on Both Macs

Before keys can authenticate, each Mac must allow incoming SSH connections.

1. Turn On Remote Login:

On both macmini.local and macbook-m3.local:

  • Open System Settings > General > Sharing,
  • then switch Remote Login on.

Note the .local address shown under Remote Login (confirming macmini.local and macbook-m3.local).

Verification:

  • Remote Login shows an active status (such as a green indicator or "On").

2. Allow SSH Through Any Active Firewall:

Optional firewall check.

If Firewall is enabled under System Settings > Network > Firewall, make sure sshd / Remote Login is allowed.

Verification:

  • Neither Mac blocks port 22 connections from the other Mac on the local network.

2. Generate SSH Keys on Each Mac

Create an Ed25519 key pair on each machine so each Mac has its own identity when connecting to the other.

(NOTE: mkdir -p will silently succeed with exit code 0 if the directory already exists.) 

# Run on macmini.local
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_macmini -N ""

# Run on macbook-m3.local
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_macbook_m3 -N ""

Verification:

  • Running ls -la ~/.ssh on each Mac shows both the private key (id_ed25519_...) and public key (id_ed25519_....pub).

3. Share Public Keys for Mutual Access

Add each Mac's public key to the other Mac's ~/.ssh/authorized_keys file so both directions work without passwords.

(Insert the <username> where indicated.) 

# From macmini.local -> authorize macmini's key on macbook-m3.local
cat ~/.ssh/id_ed25519_macmini.pub | ssh <username>@macbook-m3.local \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

# From macbook-m3.local -> authorize macbook-m3's key on macmini.local
cat ~/.ssh/id_ed25519_macbook_m3.pub | ssh <username>@macmini.local \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

You may be prompted for your <username> account password once during this initial key copy.

Verification:

  • Each machine's ~/.ssh/authorized_keys file has 600 permissions and contains the other Mac's ssh-ed25519 ... public key line.

4. Map Keys in ~/.ssh/config

Each Mac needs its own ~/.ssh/config file containing only the Host block for the other machine, using the private key stored locally on the machine you are typing from.

1. On macmini.local (to connect out to macbook-m3.local)

Open ~/.ssh/config in a text editor such as nano ~/.ssh/config and add this block (pointing to macmini.local's local private key, id_ed25519_macmini):

(Insert the <username> where indicated.) 

Host macbook-m3.local
  HostName macbook-m3.local
  User <username>
  IdentityFile ~/.ssh/id_ed25519_macmini
  IdentitiesOnly yes

Save the file (Ctrl + O, Return, Ctrl + X in nano), then set its permissions: 

chmod 600 ~/.ssh/config

Verification:

  • Running cat ~/.ssh/config on macmini.local shows only the Host macbook-m3.local block, and ls -l ~/.ssh/config shows -rw------- permissions.

2. On macbook-m3.local (to connect out to macmini.local)

Open ~/.ssh/config on macbook-m3.local (nano ~/.ssh/config) and add this block (pointing to macbook-m3.local's local private key, id_ed25519_macbook_m3):

(Insert the <username> where indicated.) 

Host macmini.local
  HostName macmini.local
  User <username>
  IdentityFile ~/.ssh/id_ed25519_macbook_m3
  IdentitiesOnly yes

Save the file (Ctrl + O, Return, Ctrl + X in nano), then set its permissions: 

chmod 600 ~/.ssh/config

Verification:

  • Running cat ~/.ssh/config on macbook-m3.local shows only the Host macmini.local block, and ls -l ~/.ssh/config shows -rw------- permissions.

5. Test Interactive and BatchMode Connections

Verify both interactive shell logins and non-interactive commands from each machine.

(Insert the <username> where indicated.) 

# From macmini.local to macbook-m3.local
ssh -o BatchMode=yes -o ConnectTimeout=5 <username>@macbook-m3.local "hostname && uptime"

# From macbook-m3.local to macmini.local
ssh -o BatchMode=yes -o ConnectTimeout=5 <username>@macmini.local "hostname && uptime"

Verification:

  • Both commands print the target machine's hostname and uptime immediately without asking for a password or passphrase, and typing exit inside an interactive ssh session returns to your local prompt.

With key-based SSH enabled between macmini.local and macbook-m3.local, you can open interactive shells, run remote commands without typing a password, and transfer files or scripts cleanly over your local network.

Logging Into a Remote Mac

Connect using the target machine's .local hostname and your <username> account. Because your BatchMode Ed25519 keys are already set up, connections authenticate automatically when the matching key is available.

Basic Connection Commands

  • From macmini.local to macbook-m3.local:

(Insert the <username> where indicated.) 

ssh <username>@macbook-m3.local
  • From macbook-m3.local to macmini.local:

(Insert the <username> where indicated.) 

ssh <username>@macmini.local
  • Explicitly specify an identity file (useful if testing or bypassing defaults):

(Insert the <username> where indicated.) 

ssh -i ~/.ssh/id_ed25519_macbook_m3 <username>@macbook-m3.local

This command connects over SSH to macbook-m3.local while forcing SSH to use one specific private key file instead of trying default key names.

How Each Part Works

  • ssh: Starts the Secure Shell client to open a remote session.
  • -i ~/.ssh/id_ed25519_macbook_m3: Tells SSH which identity file (your private key) to offer for authentication. Without -i, SSH automatically checks default key names (like id_ed25519 or id_rsa) and may try multiple keys if you have several.
  • <username>: Replace this placeholder with your actual macOS account short username on macbook-m3.local (for example, alex).
  • @macbook-m3.local: Specifies the target host on your local network using its Bonjour/mDNS hostname.

Why Use -i Here?

  • Testing a specific key: Confirms that id_ed25519_macbook_m3 and its matching .pub entry in ~/.ssh/authorized_keys on the MacBook are set up properly.
  • Bypassing defaults or avoiding lockouts: If you have many keys, some SSH servers limit how many authentication attempts a client can make before rejecting the connection (Too many authentication failures). Pointing directly to the right key avoids wasted attempts.

Practical Tip for Everyday Use

Typing -i every time gets repetitive. Once you verify that this command logs in cleanly, you can save the key preference in ~/.ssh/config on the connecting machine so plain ssh macbook-m3.local uses that key automatically.

  • Exit back to your local machine:

Disconnecting from SSH Connection

Type exit and press Return (or press Ctrl + D on an empty line).

Verifying Key Authentication Without Prompting

Test non-interactive authentication before automating anything:

(Insert the <username> where indicated.) 

ssh -o BatchMode=yes -o ConnectTimeout=5 <username>@macbook-m3.local "hostname && uptime"

If that prints the hostname and uptime without asking for a password or passphrase, key-based login is working cleanly.

Privacy Layer

The macOS privacy layer restricts remote SSH sessions (sshd) from accessing protected user directories like Documents, Desktop, and Downloads by default. Even though your user account owns the files, the remote login daemon lacks explicit Full Disk Access.

To grant the necessary permissions, follow these steps on the target Mac (the machine you are SSHing into):

1. Open Full Disk Access Settings: System Settings.

  • Open System Settings on the target Mac, navigate to Privacy & Security, and click on Full Disk Access.

Verification:

  • You see a list of apps and background services with toggle switches.

2. Locate and Add the SSH Daemon: Requires admin authentication.

  • Click the + (plus) button.
  • When the file selection window pops up, press Command + Shift + G to open the "Go to the folder" shortcut bar.
  • Type /usr/sbin/sshd into the box, press Return, and click Open.

Verification:

  • sshd appears in your Full Disk Access list.

3. Enable Full Disk Access: Activate the toggle.

  • Ensure the toggle switch next to sshd is turned on (blue).
  • Authenticate with your Mac password or Touch ID when prompted.

Verification:

  • The switch for sshd is visibly enabled.

4. Restart Remote Login: Refresh the SSH service.

  • Go to System Settings > General > Sharing,
  • Toggle Remote Login off, wait a few seconds, and turn it back on.
  • This restarts the SSH daemon so it loads the updated permissions.

Verification:

  • Remote Login is active again.

Verification:

  • SSH back into the target Mac from your client machine and run ls Documents again. The folder contents will now list successfully without error.

Practical Examples Between Your Two Macs

Once SSH works in BatchMode, you can treat the remote Mac as an extension of your terminal for quick checks, remote script execution, and file movement.

1. Run a Command Remotely Without Opening a Full Session

Pass a command string right after the host to execute it on the remote Mac and return immediately:

(Insert the <username> where indicated.) 

# Check free disk space on macbook-m3.local
ssh <username>@macbook-m3.local "df -h /"

# Check if Manager.io is running on macmini.local
ssh <username>@macmini.local "ps -axo pid,comm,args | grep -E 'ManagerDesktop|ManagerServer|/Manager([[:space:]]|$)' | grep -v 'grep -E'"

2. Copy Scripts or Files Between Machines

(Insert the <username> where indicated.)

Use scp or rsync when moving files or syncing scripts like /Users/<username>/bin/sync_manager.sh: 

# Copy updated sync_manager.sh from macmini.local to macbook-m3.local
scp /Users/<username>/bin/sync_manager.sh <username>@macbook-m3.local:/Users/<username>/bin/sync_manager.sh

# Preview copying a single file with rsync
rsync -avi --dry-run /Users/<username>/bin/sync_manager.sh <username>@macbook-m3.local:/Users/<username>/bin/sync_manager.sh

--dry-run tells rsync to simulate the transfer and print what it would do without actually copying, modifying, or deleting any files on the destination (macbook-m3.local).

Why Use --dry-run Before Syncing?

  • Safe preview: Lets you confirm rsync is targeting the right source and destination paths before overwriting files or creating changes on macbook-m3.local.
  • Inspects exact changes (-avi): Combined with -avi (archive mode, verbose, itemized changes), it shows which files would be transferred and why (for example, new file, changed size, or changed timestamp) without making any edits yet.
  • Catches path or connection errors early: Verifies SSH reachability and path validity before a real transfer runs.

How to Run the Real Copy Afterward

Once the --dry-run output looks right, remove --dry-run to perform the actual transfer: 

rsync -avi /Users/<username>/bin/sync_manager.sh <username>@macbook-m3.local:/Users/<username>/bin/sync_manager.sh
  • Verification: rsync transfers the file over SSH and exits with status 0; if the file already matches on the destination, it reports no transfer needed.

Explaining the -avi flags

In rsync -avi, -avi combines three flags (-a, -v, -i), and each transferred item gets an itemized change code on the left.

What the -avi Flags Do

  • -a (archive mode): Preserves permissions, timestamps, owner/group (when permitted), symlinks, and recursive behavior—equivalent to -rlptgoD.
  • -v (verbose): Prints progress and summary transfer statistics.
  • -i (itemize changes): Prints a structured change code before each file or directory path so you can see why rsync is acting on it.

Itemized Output Codes (-i)

A typical line looks like: 

>f..t...... sync_manager.sh

Here is how to read the main parts of that code:

  • Position 1 (action/direction):
    • > means the file is being transferred to the receiver (macbook-m3.local).
    • c means a local change or creation is happening (such as creating a directory or symlink).
    • . means the item is not being transferred (attributes only or already up to date).
  • Position 2 (file type):
    • f = regular file, d = directory, L = symlink.
  • Remaining characters (what changed):
    • s = file size differs.
    • t = modification time differs (with -a, rsync updates the remote timestamp to match).
    • p = permissions differ.
    • o / g = owner or group differs.
    • A dot (.) in any slot means that attribute matches and is unchanged.

Quick Examples to Watch For

  • >f+++++++++ sync_manager.sh: A brand-new file being created on the destination.
  • >f.st...... sync_manager.sh: An existing file being updated because both its size (s) and timestamp (t) changed.
  • >f..t...... sync_manager.sh: A file being updated where only the timestamp (t) or metadata changed (or byte size happened to match).
  • No line for sync_manager.sh: The file already matches on the destination, so rsync skips it.

3. Trigger a Sync or Check Remotely

(Insert the <username> where indicated.)

You can run /Users/<username>/bin/sync_manager.sh directly on the remote machine over SSH when you want to trigger a run from the other Mac: 

# Run a dry-run sync check on macbook-m3.local from macmini.local
ssh <username>@macbook-m3.local "/Users/<username>/bin/sync_manager.sh --dry-run"

4. Stream Remote Logs or Output Live

Watch output from a remote command in real time in your local terminal:

(Insert the <username> where indicated.) 

# Stream recent system log entries for sshd or login activity on macbook-m3.local
ssh <username>@macbook-m3.local "log show --last 15m --predicate 'process == \"sshd\"' --style compact"
