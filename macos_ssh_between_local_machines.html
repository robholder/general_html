SSH on Local Network

Here is a guide for setting up passwordless SSH between macmini.local and macbook-m3.local so interactive logins, file transfers, and BatchMode commands work smoothly.

1. Enable Remote Login on Both Macs

Before keys can authenticate, each Mac must allow incoming SSH connections.

1. Turn On Remote Login:

On both macmini.local and macbook-m3.local:

Open System Settings > General > Sharing, then switch Remote Login on. Note the .local address shown under Remote Login (confirming macmini.local and macbook-m3.local).

Verification:

  • Remote Login shows an active status (such as a green indicator or "On").

2. *Allow SSH Through Any Active Firewall:

Optional firewall check.

If Firewall is enabled under System Settings > Network > Firewall, make sure sshd / Remote Login is allowed.

Verification:

  • Neither Mac blocks port 22 connections from the other Mac on the local network.

2. Generate SSH Keys on Each Mac

Create an Ed25519 key pair on each machine so each Mac has its own identity when connecting to the other. 

# Run on macmini.local
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_macmini -N ""

# Run on macbook-m3.local
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_macbook_m3 -N ""

Verification:

  • Running ls -la ~/.ssh on each Mac shows both the private key (id_ed25519_...) and public key (id_ed25519_....pub).

3. Share Public Keys for Mutual Access

Add each Mac's public key to the other Mac's ~/.ssh/authorized_keys file so both directions work without passwords. 

# From macmini.local -> authorize macmini's key on macbook-m3.local
cat ~/.ssh/id_ed25519_macmini.pub | ssh noddy@macbook-m3.local \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

# From macbook-m3.local -> authorize macbook-m3's key on macmini.local
cat ~/.ssh/id_ed25519_macbook_m3.pub | ssh noddy@macmini.local \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

You may be prompted for your noddy account password once during this initial key copy.

Verification:

  • Each machine's ~/.ssh/authorized_keys file has 600 permissions and contains the other Mac's ssh-ed25519 ... public key line.

4. Map Keys in ~/.ssh/config

Each Mac needs its own ~/.ssh/config file containing only the Host block for the *other* machine, using the private key stored locally on the machine you are typing from.

1. On macmini.local (to connect out to macbook-m3.local)

Open ~/.ssh/config in a text editor such as nano ~/.ssh/config and add this block (pointing to macmini.local's local private key, id_ed25519_macmini): 

Host macbook-m3.local
  HostName macbook-m3.local
  User noddy
  IdentityFile ~/.ssh/id_ed25519_macmini
  IdentitiesOnly yes

Save the file (Ctrl + O, Return, Ctrl + X in nano), then set its permissions: 

chmod 600 ~/.ssh/config

Verification:

  • Running cat ~/.ssh/config on macmini.local shows only the Host macbook-m3.local block, and ls -l ~/.ssh/config shows -rw------- permissions.

2. On macbook-m3.local (to connect out to macmini.local)

Open ~/.ssh/config on macbook-m3.local (nano ~/.ssh/config) and add this block (pointing to macbook-m3.local's local private key, id_ed25519_macbook_m3): 

Host macmini.local
  HostName macmini.local
  User noddy
  IdentityFile ~/.ssh/id_ed25519_macbook_m3
  IdentitiesOnly yes

Save the file (Ctrl + O, Return, Ctrl + X in nano), then set its permissions: 

chmod 600 ~/.ssh/config

Verification:

  • Running cat ~/.ssh/config on macbook-m3.local shows only the Host macmini.local block, and ls -l ~/.ssh/config shows -rw------- permissions.

5. Test Interactive and BatchMode Connections

Verify both interactive shell logins and non-interactive commands from each machine. 

# From macmini.local to macbook-m3.local
ssh -o BatchMode=yes -o ConnectTimeout=5 noddy@macbook-m3.local "hostname && uptime"

# From macbook-m3.local to macmini.local
ssh -o BatchMode=yes -o ConnectTimeout=5 noddy@macmini.local "hostname && uptime"

Verification:

  • Both commands print the target machine's hostname and uptime immediately without asking for a password or passphrase, and typing exit inside an interactive ssh session returns to your local prompt.

With key-based SSH enabled between macmini.local and macbook-m3.local, you can open interactive shells, run remote commands without typing a password, and transfer files or scripts cleanly over your local network.

Logging Into a Remote Mac

Connect using the target machine's .local hostname and your noddy account. Because your BatchMode Ed25519 keys are already set up, connections authenticate automatically when the matching key is available.

Basic Connection Commands

  • *From macmini.local to macbook-m3.local:* 
    ssh noddy@macbook-m3.local
  • *From macbook-m3.local to macmini.local:* 
    ssh noddy@macmini.local
  • Explicitly specify an identity file (useful if testing or bypassing defaults): 
    ssh -i ~/.ssh/id_ed25519_macbook_m3 noddy@macbook-m3.local
  • Exit back to your local machine:

Type exit and press Return (or press Ctrl + D on an empty line).

Verifying Key Authentication Without Prompting

Test non-interactive authentication before automating anything: 

ssh -o BatchMode=yes -o ConnectTimeout=5 noddy@macbook-m3.local "hostname && uptime"

If that prints the hostname and uptime without asking for a password or passphrase, key-based login is working cleanly.

Practical Examples Between Your Two Macs

Once SSH works in BatchMode, you can treat the remote Mac as an extension of your terminal for quick checks, remote script execution, and file movement.

1. Run a Command Remotely Without Opening a Full Session

Pass a command string right after the host to execute it on the remote Mac and return immediately: 

# Check free disk space on macbook-m3.local
ssh noddy@macbook-m3.local "df -h /"

# Check if Manager.io is running on macmini.local
ssh noddy@macmini.local "pgrep -if 'Manager' || echo 'Not running'"

2. Copy Scripts or Files Between Machines

Use scp or rsync when moving files or syncing scripts like /Users/noddy/bin/sync_manager.sh: 

# Copy updated sync_manager.sh from macmini.local to macbook-m3.local
scp /Users/noddy/bin/sync_manager.sh noddy@macbook-m3.local:/Users/noddy/bin/sync_manager.sh

# Preview copying a single file with rsync
rsync -avi --dry-run /Users/noddy/bin/sync_manager.sh noddy@macbook-m3.local:/Users/noddy/bin/sync_manager.sh

3. Trigger a Sync or Check Remotely

You can run /Users/noddy/bin/sync_manager.sh directly on the remote machine over SSH when you want to trigger a run from the other Mac: 

# Run a dry-run sync check on macbook-m3.local from macmini.local
ssh noddy@macbook-m3.local "/Users/noddy/bin/sync_manager.sh --dry-run"

4. Stream Remote Logs or Output Live

Watch output from a remote command in real time in your local terminal: 

# Stream recent system log entries for sshd or login activity on macbook-m3.local
ssh noddy@macbook-m3.local "log show --last 15m --predicate 'process == \"sshd\"' --style compact"

Quick Troubleshooting Checklist

Symptom Likely Cause Quick Check
Permission denied (publickey) in BatchMode Wrong key used or public key missing from ~/.ssh/authorized_keys on target Run with -v (ssh -v noddy@macbook-m3.local) to see which key file is offered
Could not resolve hostname ...local Bonjour/mDNS lookup delayed or Wi-Fi/Ethernet interface sleeping Wake the target Mac or verify its hostname in System Settings > General > Sharing
Connection hangs and times out Remote Login (SSH) disabled or firewall blocking port 22 Enable Remote Login under System Settings > General > Sharing on the target Mac
