Linux/macOS rsync Command: Reference & Practical Guide

rsync (Remote Sync) is one of the most powerful, flexible, and efficient tools in the Unix, Linux, and macOS ecosystem. What makes it legendary is its delta-transfer algorithm, meaning it only copies the exact bytes that have actually changed (or new files), saving immense amounts of time and bandwidth compared to tools like cp or scp.

1. Quick Start / Example Usage

# Backup documents to a local thumbdrive (simulating first with dry-run)
rsync -avh --progress --dry-run ~/Documents/ /Volumes/BackupDrive/Docs/

2. Core Anatomy of an rsync Command

The basic syntax is always: 

rsync [options] /path/to/source/ /path/to/destination/

The "Trailing Slash" Trap ⚠️

The presence or absence of a *trailing slash (/) on the source folder* completely changes what happens:

  • *With a trailing slash (source/):* Copies the contents inside the folder into the destination. 
    rsync -a /my/photos/ /backup/
# Result: /backup/pic1.jpg, /backup/pic2.jpg
  • Without a trailing slash (source): Copies the folder itself into the destination. 
    rsync -a /my/photos /backup/
# Result: /backup/photos/pic1.jpg, /backup/photos/pic2.jpg

3. Essential Flags Reference

Flag Name Description
-a Archive Mode Shorthand for -rlptgoD (recursive, symlinks, permissions, modification times, groups, owners). Always use this for backups.
-v Verbose Prints information on what files are being transferred.
-h Human-readable Displays file sizes in a readable format (e.g., KB, MB, GB).
-z Compress Compresses file data during transmission (crucial for remote/SSH transfers, unnecessary for local USB backups).
-P Partial / Progress Equivalent to --partial --progress. Shows progress bars and allows resuming interrupted transfers.
-n or --dry-run Dry Run Always use this first! Simulates the sync without modifying any files to verify behavior.
--delete Delete Deletes files in the destination directory if they no longer exist in the source (creates an exact mirror).
--exclude='pattern' Exclude Skips files or directories matching the pattern (e.g., --exclude='*/.snapshot/').

4. Practical Copying Scenarios

A. Local Backup

rsync -avh --progress ~/Documents/ /Volumes/BackupDrive/Docs/

B. Remote Backup over SSH

# Push local folder to a remote server
rsync -avhz -e ssh ~/Documents/ user@remotehost:/path/to/remote/dir/

# Pull remote folder to your local machine
rsync -avhz -e ssh user@remotehost:/path/to/remote/dir/ ~/LocalDest/

C. Excluding Unwanted Files (e.g., .snapshot directories)

Network-attached storage systems (ZFS, NetApp, Isilon) often automatically create hidden .snapshot folders. To exclude them cleanly at any depth: 

rsync -avh --exclude='**/.snapshot/' /source/images/ /destination/images/
  • */.snapshot: Matches .snapshot folders only one level deep.
  • **/.snapshot: Matches .snapshot folders at any depth in the tree (recommended).

5. Advanced Strategies: Time-Machine-Style Backups (--link-dest)

You can create point-in-time incremental snapshots without wasting immense storage space by leveraging hard links. If a file hasn't changed, rsync links to the previous backup rather than copying it again.

Example Snapshot Script (backup.sh):

#!/bin/bash
SRC="$HOME/Documents/"
BACKUP_ROOT="/Volumes/BackupDrive/Snapshots"
LATEST="$BACKUP_ROOT/latest"
CURRENT="$BACKUP_ROOT/backup_$(date +%Y-%m-%d_%H%M%S)"

# Create new snapshot using the previous 'latest' folder for comparison
rsync -avh --delete \
  --link-dest="$LATEST" \
  "$SRC" \
  "$CURRENT"

# Update the 'latest' symlink to point to the fresh backup
rm -f "$LATEST"
ln -s "$CURRENT" "$LATEST"
  • How it restores: Because every snapshot folder is a fully realized directory via hard links, you can browse them normally in Finder/Explorer and drag-and-drop restored files directly. Deleting old snapshots (rm -rf) is safe because hard links only release data when all references are gone.

6. macOS vs. Linux Quirks

If you are syncing between a Mac and a Linux machine, keep these two critical differences in mind:

  1. The Engine Version:
  2. Linux ships with modern rsync 3.x (incremental scanning).
  3. macOS ships with an ancient rsync 2.6.9 due to GPLv3 licensing. It scans the entire tree into memory before sending files, which can feel sluggish on massive repos.
  4. Fix: Install a modern version via Homebrew: brew install rsync.
  5. Extended Attributes (Mac Metadata):
  6. macOS stores Finder tags, colors, and resource forks in extended attributes. To preserve these on Mac-to-Mac or Mac-to-Linux transfers, add the *-E* (or --extended-attributes) flag: 
rsync -avzE --delete source/ dest/
